## How each page was done

Each page was rewritten to the how-to template: overview, prerequisites, how it works, steps, a complete example, verification, troubleshooting and references.

- **Facts:** every directive name, default, context and version note was checked against the source: the `ngx_command_t` tables, the `ngx_conf_merge_*` calls, and `git tag --contains` for versions.
- **Examples:** every config example passes `nginx -t`. Fragments were wrapped in the minimal surrounding contexts. The complete example and the verification steps were run with a real nginx and `curl`, or `openssl`, `htpasswd` and `ss` where the page uses them.
- **Diagrams:** each was validated with the Mermaid CLI and has a text description next to it.
- **Checks:** each page lints clean, link-checks with no new failures, and builds with Hugo.
- **Review:** a fresh reviewer then followed each page literally on a running nginx, and everything that reviewer found was fixed and checked again. Page 9 was committed before its review and fixed in a follow-up commit, `46f7e06e`.

## Defects fixed

The page that each fix applies to is in brackets. Source references are in the nginx repository. All of these are factual corrections, which [Decisions](#decisions) item 1 covers.

- **[configuration files]**
  - `nginx -T` shows the files on disk, not the loaded configuration.
  - Reload errors appear either in the terminal or only in the error log.
  - `add_header_inherit` exists (`ngx_http_headers_filter_module.c:107-155`).
  - Wildcard includes are sorted by byte value.
- **[web server]**
  - `open_file_cache_errors` was described as suppressing "file not found" messages. It controls caching of lookup errors, and `log_not_found` is the right directive.
  - The `sub_filter_once` description was reversed.
  - The location search order now includes nested and predicate locations (1.31.5, `5f54125dd`).
  - `break` in a `server` context still leads to a location search.
  - `return` also redirects with 308.
  - Fixed a typo URL, a garbled sentence about `$1` and a duplicate anchor.
- **[reverse proxy]**
  - Since 1.29.7 (`6bb27a631`), nginx proxies with HTTP/1.1 and sends no `Connection: close`. Keepalive is the default for upstream groups (`4fbe4b627`).
  - A `proxy_pass` URI in a regex location is rejected by `nginx -t`.
  - Empty client headers are passed, and `Host ""` is special since 1.31.4.
  - The "too big header" fix failed the busy-buffers check.
  - `proxy_bind` to loopback can't reach remote servers.
  - Fixed the buffering description.
- **[load balancing]**
  - These are in NGINX Open Source, and several were labelled NGINX Plus only: Random (1.15.1), `sticky` (1.29.6), `least_time` (1.31.0), `resolve` (1.27.3) and `max_conns`.
  - Weights apply to all methods.
  - `ip_hash`, `hash` and `random` reject `backup`.
  - Corrected when backup servers are used, the single-server rule, the retry conditions and the Exchange port (443).
  - Correction to this page's first version: `max_fails` failures don't have to happen within `fail_timeout`. The count is reset only by a success that NGINX sent more than `fail_timeout` after the last failure (`ngx_http_upstream_round_robin.c:924-926, 1084-1086`). Fixed in `69c66c16`, also on page 13.
- **[content caching]**
  - Responses aren't cached "indefinitely": without a validity time they aren't cached at all, and `inactive` (10 minutes) removes unused entries.
  - Bypassed requests still store their responses.
  - Cache purge is NGINX Plus only.
  - The purge `curl` command used an en dash.
  - Removed a duplicate `map`.
  - nginx creates only the last directory of `proxy_cache_path`.
- **[TLS]**
  - TLSv1.2 and TLSv1.3 became the default in 1.27.3 (`476d6526b`), not 1.23.4.
  - The `ssl` directive was removed in 1.25.1, not just deprecated.
  - Removed a corrupted "Chrome 105" SNI entry.
  - Updated the key-mismatch error text for OpenSSL 3.
  - Examples lacked `ssl_certificate_key`.
  - The 0.8.19 protocol defaults were wrong.
  - Described the `ssl_ocsp` `on` and `leaf` modes.
- **[rate limiting]**
  - Without `burst`, excess requests are rejected at once; the page said they were delayed.
  - A zone holds about 8,000 states per MB, not 16,000.
  - The `$server_name` example limited nothing.
  - `limit_rate` applies per request.
  - Limits don't apply to `return`.
  - `sync` is NGINX Plus only.
- **[logging]**
  - The syslog `severity=` default is `info`, not `error`, and it labels messages rather than filtering them.
  - Upstream times print `-` when a time wasn't measured, and are separated by `, ` and ` : `, not semicolons.
  - The syslog facility list was wrong.
  - JSON error logs and `keyval` are NGINX Plus only.
- **[basic authentication]**
  - `allow 192.168.1.1/24` made nginx warn about meaningless address bits.
  - The complete example used the NGINX Plus `api` directive.
  - `conf/htpasswd` resolved to a file that no step creates.
  - A missing password file gives 403, not 500.
- **[runtime control]**
  - Corrected the Control API endpoints and responses.
  - Workers use `user` only when the master runs as root.
  - `worker_processes auto` counts logical CPUs.
  - Fixed when the cache processes run.
  - Fixed the "NIGNX" typo.
- **[static content]**
  - A directory without an index file returns 403, not 404, and a directory URI without a trailing slash gets a 301.
  - `tcp_nodelay` isn't keepalive-only, and the "200 ms" claim was wrong.
  - `netstat -Lan` is FreeBSD syntax; the Linux equivalent is `ss -lnt`.
  - The default backlog is 511.
  - The `$geo` example had no `geo` block.
- **[TCP/UDP load balancing]**
  - The connect and failover description was TCP-only; UDP datagrams aren't retried and `proxy_connect_timeout` doesn't apply.
  - Fixed the step numbering, a `proxy_bind` example that couldn't reach a remote server, a stream server without `listen`, an API `PATCH` call to the HTTP path, a zone name mismatch and an empty upstream group.
  - Added UDP sessions (`proxy_responses`, `proxy_requests`, `proxy_timeout`), weighted Least Connections and the required `least_time` parameter.
- **[HTTP health checks]**
  - Only listed 5xx statuses that make NGINX try the next server count as failures. A 5xx from the last server tried, or for a `POST` without `non_idempotent`, doesn't count (`ngx_http_upstream.c:4628-4637`).
  - After `fail_timeout`, NGINX sends one trial request, not several. Without a `zone`, each worker counts failures separately.
  - The `upstream server temporarily disabled` message is logged at `warn`, so the default error log level hides it.
  - Fixed a backup address outside the documentation range, and a mandatory-check example that contradicted the `slow_start` single-server rule.
- **[TCP health checks]**
  - With `proxy_ssl`, a failed TLS handshake also counts as a failure. Errors on an established connection don't.
  - Fixed an upstream port typo (12346) and a backup address outside the documentation range. Added the stream module prerequisite.
- **[UDP health checks]**
  - The passive example claimed "2 failures" but didn't set `max_fails`.
  - The NTP example used port 53 instead of 123, and the hex prefix was written `/x`.
  - The DNS `expect` regular expression could never match: a DNS response encodes the CNAME target as length-prefixed labels with a compression pointer, so the dotted name isn't in it. See [Decisions](#decisions) item 6.
  - A failed `connect()` is the only UDP failure that NGINX retries on another server. ICMP errors without `proxy_responses` count only when the session ends.
- **[gRPC health checks]**
  - The upstream group was in the `stream` context, where `grpc_pass` can't find it: `nginx -t` failed with `no port in upstream`.
  - `location /grpc` doesn't match gRPC request paths, which look like `/package.Service/Method`.
  - Added `http2 on` (1.25.1), the `--with-http_v2_module` build requirement, and that the gRPC server must be the default server of its port.
- **[PROXY protocol]**
  - The examples failed `nginx -t`: `log_format combined` redefined a predefined format, and the stream format used `$remote_user`, which doesn't exist in the stream module.
  - Client-side PROXY protocol in stream arrived in 1.9.2, not 1.9.3. Added 1.11.0 for ports, 1.17.6 for the server address variables, and `proxy_protocol v2` to upstreams (1.31.4).
  - The `listen` parameter applies to every server on that address and port. `$proxy_protocol_addr` isn't filtered by `set_real_ip_from`. HTTP/3 and UDP aren't supported. Removed SPDY.
- **[dynamic configuration API]**
  - The `POST` body had backslashes inside single quotes and wasn't valid JSON. The write requests had no credentials for the page's own `auth_basic` setup, so they got `401`. The examples deleted server 0 before changing it.
  - The API location was shown as a separate `server` block that wouldn't get requests.
  - From the repository's release notes: `upstream_conf` was removed in R16; API version 9 needs R30; the Swagger UI isn't in packages since R26.
- **[compression]**
  - Corrected the `gzip_proxied` logic.
  - Added `.xml` as `text/xml`.
  - `gunzip` and `gzip_static` use the same client checks.
  - `gunzip` doesn't act on files stored on disk.

- **[TCP TLS termination]**
  - `ssl_session_cache;` without a parameter fails `nginx -t`. The default cache is `none`, not the built-in cache.
  - With session tickets, TLSv1.3 sessions aren't stored in the cache; since 1.23.2 the shared cache holds the ticket keys (`ngx_event_openssl.c:4445`).
  - NGINX doesn't close the client connection. Ticket keys are shared between NGINX instances, not upstream servers, and both key files must exist.
  - Only the default server of a port is checked for a certificate. Added SNI virtual servers (1.25.5), variable certificates with a `map` default, and TLSv1.3 cipher suites.
- **[upstream HTTPS]**
  - The complete example was missing a brace. `ssl_verify_client optional` doesn't require client certificates, and `ssl_client_certificate` is a CA file.
  - `proxy_ssl_verify` is off by default, and the name checked defaults to the upstream group name with SNI off, so the example failed with `does not match`.
  - A `Host` header that isn't exactly the SNI name gives `421` when the upstream port has several servers (`ngx_http_request.c:2490`).
  - A server without a port in an upstream group uses port 80, even with `https`. `proxy_ssl_verify_depth 1` allows one intermediate certificate (tested with chains).
- **[upstream TCP TLS]**
  - The fragments contained `...`. The same `proxy_ssl` defaults as for HTTP.
  - An upstream that rejects NGINX's client certificate closes the connection after the handshake, so NGINX logs nothing and doesn't retry.
  - Without `zone`, round-robin order and saved TLS sessions are per worker process.
- **[TCP access control]**
  - `allow 192.168.1.1/24` makes `nginx -t` warn. The `limit_conn_zone` links pointed to the HTTP module, and the zone's purpose was wrong.
  - `limit_conn` runs before `allow`/`deny`, and a client that matches no rule is allowed. The IPv6 rule needs an IPv6 `listen`.
- **[GeoIP]**
  - The "nearest server" example failed in both contexts: `proxy_pass http://` isn't valid in `stream`, and in `http` `proxy_pass` must be in a `location`. Its map sent clients to groups that didn't exist.
  - The `geolite.maxmind.com` download URLs no longer respond; the databases need a MaxMind account. `mmdblookup` is in `mmdb-bin` on Ubuntu, and the syntax line used en dashes.
  - Relative database paths are relative to the prefix. Only one `geoip2` block per file. Added deny-by-country examples.
- **[subrequest authentication]**
  - Any status other than 2xx, 401 and 403 gives `500`. The subrequest is a `GET` for `/auth` without a body, but with the original `Content-Length` header.
  - The check runs in the access phase: `return` and `rewrite` run first, and a regex location can bypass a prefix location. The examples use `^~`.
- **[JWT]** (NGINX Plus)
  - `proxy_pass "https_//..."` fails `nginx -t`; the nested-JWT example had `upstream` outside `http` and `proxy_pass` in a `server` block.
  - The claim maps used unanchored regular expressions with unescaped dots, so a token for `api1xexample.com.attacker.net` passed. The key location wasn't `internal`, and the key fetch didn't verify the IdP's certificate.
  - The 401/403 example could never return `403`, because the scope check was in both `auth_jwt_require` lines. JWS public keys were combined with `auth_jwt_type encrypted`; the example now uses `nested`.
  - OpenID Connect Core doesn't require checking `sub`. The example secret is shorter than RFC 7518 requires for HS256. Added a test token made with `openssl`, checked against the page's key.
- **[OIDC]** (NGINX Plus)
  - `userinfo_endpoint` and `end_session_endpoint` were described wrongly, and the discovery URL left out the issuer path. The `issuer` link pointed to `#client_secret`.
  - The IdP setup didn't register the redirect URI, and registered the wrong logout URI. `session_sync_leeway` arrived after R34, according to the release notes, and the logout and UserInfo settings need R35.
  - The workflow text didn't match the numbering of the existing image.
  - The test application listened on all addresses, so clients could send their own identity headers to it.
- **[denylisting]** (NGINX Plus)
  - The API `curl` commands called `http://www.example.com/api` without credentials, but the configuration allows only `127.0.0.1` and needs a password for changes: every change got `403` or `401`.
  - Three `<span>` anchors duplicated heading IDs. Added a lockout recovery, and a warning that a broad `set_real_ip_from` lets any client pass `allow 127.0.0.1`.

They also allow core dumps after the switch on Linux (`prctl(PR_SET_DUMPABLE)`, `:904-910`). So the `prlimit`, `ulimit` and `exec su` steps and `fs.suid_dumpable` aren't needed. Checked live: a worker's limit was 524288000/524288000, while the master's stayed 0. `sysctl -p` was dropped, and the old distribution list was replaced by an explanation of `core_pattern`.

  - A per-server debug log misses the start of each request when the server isn't the default one for its `listen` address (`ngx_http_request.c:554`, `2551`).
  - Added the Control API way to get the loaded configuration (`GET /1/control/config`, 1.31.5). The GDB dump needs debug support or the Control API (`ngx_conf_file.c:222-228`) and debugging symbols.
  - Fixed the GDB scripts marked as `nginx` code, the `error_log` in a `shell` block, the `nginx.conf.txt` typo and the FreeBSD configuration path. Both GDB scripts were run against NGINX started under GDB.

## Decisions

The repository owner approved decisions 1 to 5 on 2026-11-16, decision 6 on 2026-11-17, and decisions 7 and 8 on 2026-11-20.

1. **Technical-accuracy corrections.** The repository's agent instructions say to flag technical-accuracy problems for an expert rather than fix them. The task asked for correctness against the source, so facts were corrected only where the nginx source or a running nginx proves them. Every such correction is listed in [Defects fixed](#defects-fixed).
2. **New front matter.** The changed pages gained `f5-keywords`, `f5-summary` and `f5-audience`. `f5-product` changed from `NGINX Plus` to `F5 NGINX Plus` to match the product-name list in `AGENTS.md`. No `f5-docs` ticket ID was added, because none exists.
3. **Page structure.** The pages now carry template sections that weren't there before: Example, Verify, Troubleshooting and References.
4. **No diagram on the logging page.** Diagrams were added only where they explain a flow, hierarchy or state machine.
5. **Version notes name NGINX Open Source releases only,** taken from `git tag --contains`. Matching NGINX Plus releases aren't given, because they can't be checked here.
6. **One NGINX Plus-only example was changed.** NGINX Plus facts were otherwise left as they are. The DNS health check's `expect` regular expression could never match a real DNS response, which is a fact of the DNS wire format, not of NGINX Plus. This was checked by sending the same kind of query to a real resolver and matching both expressions against the response bytes. The example now matches `healthy\x04svcs`. The `match` block itself still couldn't be run.
7. **Some NGINX Plus-only examples were changed where open-source NGINX or a public standard proves them wrong.** As with decision 6, the NGINX Plus facts themselves were kept. The changes are: configuration structure that `nginx -t` rejects (JWT), unanchored regular expressions in `map` blocks and an unverified TLS key fetch (JWT), `curl` commands that the page's own `allow`, `deny` and `auth_basic` rules reject (denylisting), and descriptions of OpenID Connect metadata fields that contradict the OpenID specifications (OIDC). Each is listed in [Defects fixed](#defects-fixed).
8. **Observations of the public NGINX Plus demo as evidence.** On the live monitoring page, the sample outputs and the top-level endpoint list were replaced with what `https://demo.nginx.com/api/10/` returned on 2026-11-19 (NGINX Plus R37.3.0, GET requests only). The demo is a running NGINX Plus maintained by F5, and its output agrees with the v10 YAML in this repository. No other NGINX Plus behaviour was changed on this basis.
